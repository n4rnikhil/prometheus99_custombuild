2. ARCHITECTURE
--------------------------------------------------------------------------------
Discovery thread (BELOW_NORMAL): every 3 s probes configured targets (default
  localhost 502 + 1502-1509; --plc addresses; opt-in --scan ranges) in batches of
  32 non-blocking connects -> FC43 Read Device Identification -> FC03 fallback.
  Reports a device ONLY if it matches a driver module with auto_attach, or was
  given explicitly with --plc. Non-PLCs go on a 60 s ignore list.
  -> SPSC candidate ring -> fieldbus thread.
Fieldbus thread (1 kHz, TIME_CRITICAL, high-res waitable timer pacer):
  heartbeat -> UI command bits + per-slot device action bits -> attach found
  devices -> device manager poll (per-slot non-blocking Modbus TCP / simulator)
  -> host telemetry -> 1 Hz per-device trends -> ISA-18.2 evaluate -> supervise
  UI heartbeat -> drain UI audit events -> CRC32-C of tag table -> seqlock publish
  (tags, alarms, watchdog, stats, device list).
UI thread (~30 Hz): snapshot + CRC verify -> fieldbus watchdog -> auto-logout ->
  horn -> log sync -> render bands. The process screen splits into one panel per
  present device (1 / 2 / 3 / 2x2) and uses each driver's full or compact manifest.
Device slot lifecycle: EMPTY -> CONNECTING -> ONLINE <-> OFFLINE -> (after
  --remove-after-ms, default 10 s) EMPTY. Removal unbinds tag meta, clears that
  slot's alarm points and trend, and journals "<label> removed".
The process opts out of Windows power throttling (EcoQoS) so background or
minimised windows keep their timing.

--------------------------------------------------------------------------------
4. KEY CONTRACTS
--------------------------------------------------------------------------------
- Tag ids: 0-31 runtime (8-11 host, 13 HMI watchdog). Device slot s owns
  HMI_DEV_TAG(s, 0..23) = 32 + 24*s + rel. HMI_MAX_TAGS = 128, HMI_MAX_DEVICES = 4.
- A driver module (hmi_device_profile_t) = identity match, needs_identity,
  auto_attach, meta (RELATIVE tag ids), FC03/FC01 block maps, actions
  (TOGGLE_COIL / TOGGLE_REG with interlock tag + labels + RBAC command), comm-loss
  tag (CRITICAL), E-stop tag/coil, trend tag, full + compact manifests.
  Manifest token tag = relative id; HMI_REL_DEVICE (23) = "device card".
- Per-slot meta copies carry group = device label ("Tank skid 2"); alarm and
  journal text is prefixed with it. Meta pointers are published with release
  ordering; a freed slot is not reused for 1.5 s so the UI never reads stale copies.
- Device labels are "<module name> <n>", n = lowest number not in use.
- Value scaling: int16 raw + meta.decimals ("842",1 -> 84.2).
- Alarm log line: seq,utc,uptime_ms,tag,SEV,STATE,"msg",crc (hash chain, genesis C001CAFE).
- Vault: 144 bytes "SECV" v1, 3 x {role, salt[8], sha256[32]}, CRC32-C.

--------------------------------------------------------------------------------
5. RULES FOR FUTURE CHANGES
--------------------------------------------------------------------------------
1. No malloc/calloc/realloc/free in application code.
2. Clean under -Wall -Wextra -Wshadow -Werror at every -O level, and cppcheck.
3. Never block the fieldbus loop; no mutexes between threads (atomics, seqlock, SPSC rings).
4. Every interactive element gets its rect from layout.c; tests hit-test it.
5. Portable modules (P) stay free of OS headers (`build.bat snapshot` proves it).
6. New PLC type = new driver module in src/drivers/profiles + registry entry;
   the core must not learn device-specific facts.
7. The HMI E-STOP is a request to the PLCs, never a safety function; never gated.
8. Network scanning stays opt-in (--scan).
9. Measure, don't claim.
